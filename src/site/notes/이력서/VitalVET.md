# 🐾 VitalVET — 동물병원 임상 SaaS

## 개요

VitalVET는 동물병원 임상 현장에서 쓰는 SaaS 제품입니다. 저는 이 중 바이탈과 처치 이력을 시간축으로 늘어놓고 진료 중 실시간으로 값을 고쳐 쓰는 **입원 차트**를 주로 맡았고, 팀 전체가 AI 코드 생성을 도입하면서 생긴 구조적 문제를 해결하는 작업도 함께 했습니다.

---

## 📊 입원 차트 재렌더 범위 축소

진료 중에 셀을 계속 고쳐 쓰는 화면이라 **입력 반응성이 곧 사용성**이었습니다. 그런데 표의 셀 하나만 수정해도 표 전체가 다시 렌더링되는 문제가 있었습니다.

- `React.memo`로 행 단위 컴포넌트를 감싸고, 상위에서 내려주는 콜백을 안정화(`useCallback`)해 참조가 매 렌더마다 바뀌지 않도록 정리
- 그 결과 셀 하나 수정 시 **재렌더 범위를 수정된 행 하나로 축소**
- 진료 중 빠르게 값을 입력해야 하는 워크플로우에서 체감 반응성이 개선됨

## 💳 흩어진 결제 폼 상태 통합

결제 폼 상태가 여러 컴포넌트에 흩어져 있어 검증 규칙을 추적하기 어려운 문제가 있었습니다.

- `react-hook-form`과 `zod`로 상태·검증 로직을 한곳에 통합
- 결제 시작, 결제 내역, 페이지뷰 이벤트 추적과 단위 테스트를 같은 자리에 배치해 상태와 검증 로직을 한눈에 확인할 수 있도록 정리
- 결과적으로 결제 관련 로직을 수정할 때 봐야 할 파일 수와 맥락이 줄어듦 (응집도 개선)

## 🛡️ AI 코드 생성 가드레일

AI 코드 생성이 늘면서 FSD(Feature-Sliced Design) 레이어 경계가 무너지는 문제가 생겼습니다. 사람이 리뷰로 매번 잡아내기엔 반복적이고 놓치기 쉬운 문제였습니다.

- 프로젝트 구조·개발 규칙을 문서화하고, 파일 수정 시점에 동작하는 **커스텀 린트 훅**을 도입
- 구조 위반 7종을 리뷰 대신 훅이 **커밋 전에 자동 차단**하도록 구성
- "규칙을 문서로만 남기지 않고 도구가 강제한다"는 원칙을 적용한 사례

## 🤝 에이전트 역할 분리

한 프롬프트에 성능 측정, 스타일링, UX 리뷰 등 모든 작업을 몰아서 맡기던 방식은 결과가 일관되지 않고 매번 같은 기준을 다시 설명해야 하는 문제가 있었습니다.

- 성능 측정, 스타일링, UX 리뷰를 각각 담당하는 **서브에이전트로 역할 분리**
- **슬래시 커맨드 9종, 스킬 13종**을 구축해 반복 작업을 표준화
- 디자인 토큰, 보호자 동의 플로우 등 반복되는 판단 기준을 UX 리뷰 스킬에 내장해 매번 재설명 없이 재사용 가능하도록 함

## 🔗 팀 간 컨텍스트 공유

인프라·백엔드·ML 팀과 협업할 때 정보를 매번 수동으로 옮기며 전달하던 문제가 있었습니다.

- 공유 레포지토리에 **inbox, 공용 컨텍스트, 의사결정 로그**를 두는 방식으로 전환
- 프론트엔드 프로젝트와 연결해 **사내 5개 프로젝트가 같은 작업 정보를 참조**하도록 구성
- 팀 간 커뮤니케이션 비용을 줄이고 의사결정 이력을 추적 가능하게 만듦
