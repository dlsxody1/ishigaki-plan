# 🏢 기업분석 · HIT (에이치아이티)

🧭 [[index\|🎯 면접 대비 홈]] · [[면접준비/기업분석\|🏢 기업분석 대시보드]] · [[면접준비/이직-공통질문\|🗣️ 이직 공통 질문]] · [[면접준비/AI-활용-경험\|🤖 AI 활용 경험]]

**서비스**: WEDDINGPRO — 웨딩업체 대상 CRM SaaS (상담 → 방문 → 계약 → 정산 통합 관리)
**포지션**: 풀스택 (NestJS 서버 개발 + React 웹 + Flutter Web)
**기술 스택**: NestJS, MySQL, React, Flutter, AWS, Google Cloud Platform
**전형**: 서류 접수 → 실무 면접 → 임원 면접 → 최종 합격

## 🔍 회사가 뭘 하는 곳인가

- 웨딩업체는 한 건당 수천만 원 매출이 오가는데도, 아직 종이 상담카드·전화·엑셀로 운영되는 경우가 많다는 문제의식에서 출발한 CRM 제품
- **상담 → 방문 → 계약 → 정산**까지 하나의 흐름으로 연결해, 운영 효율과 예약률을 높이는 게 제품의 핵심 가치
- 즉 이 제품의 본질은 "예약/영업 파이프라인 관리 + 복잡한 정산 로직을 다루는 B2B SaaS"

## 🧭 채용공고에서 읽어낸 회사의 태도

채용공고 말미에 이런 문장이 있음:

> "AI 코딩 도구는 이미 실무의 기본값입니다. 덕분에 구현 속도는 확실히 빨라졌습니다. 다만 저희는 여기서 한 걸음 더 갑니다. 이 코드가 왜 이렇게 동작하는지, 이 변경이 어디까지 영향을 미치는지를 파악하는 속도까지 같이 끌어올립니다. (...) 빠르게 만들되 이해하지 못한 채로 두지 않는 것. 추상적인 수준의 설계와 구체적인 테스트 코드로 늘 통제권을 확인하는 것."

이건 **내 이력서의 핵심 메시지와 거의 그대로 맞아떨어지는 지점**이다. 면접에서 반드시 이 연결고리를 직접 언급할 것.

- "AI가 만든 코드도 구조를 지키게 만든다" (커스텀 린트 훅, 구조 위반 7종 자동 차단) ↔ "코드가 왜 이렇게 동작하는지 파악하는 속도"
- "단위 테스트 25개로 리스크 큰 로직 검증, tsc·린트·빌드 CI화" ↔ "구체적인 테스트 코드로 통제권 확인"
- "서브에이전트 역할 분리 + 슬래시 커맨드 9종·스킬 13종" ↔ "AI 코딩 도구를 실무에 적극 활용"

> [!tip] 이 회사에서 가장 강하게 어필할 포인트
> 자기소개나 지원동기에서 이 문장을 직접 인용하며 "제가 지금 회사에서 해온 일이 정확히 이 문제의식과 같습니다"로 시작하면 강한 인상을 줄 수 있음.

## ⚠️ 솔직하게 짚어야 할 갭 (중요)

채용공고의 필수 요건을 내 이력서와 비교하면 명확한 차이가 있음. 면접에서 반드시 나올 질문이니 회피하지 말고 미리 답을 만들어둘 것.

| 요구 사항 | 내 실제 경험 | 갭 |
| --- | --- | --- |
| NestJS + TypeScript REST API 서버 개발 **3년 이상** | Spring Boot(퀀텀에이아이), FastAPI(CancerVET) 경험은 있으나 **NestJS 실무 경험 없음** | NestJS 자체 경험 없음 — 단, 데코레이터 기반 계층형 아키텍처(Controller-Service-Repository)는 Spring Boot로 직접 구현해본 경험 있음 |
| React + TypeScript **3년 이상** | 총 경력 2년 3개월(React 중심) | 연차 자체가 요건에 못 미침 |
| Flutter 개발 경력 **3년 이상** | **Flutter 경험 전무** | 가장 큰 갭. 정면 돌파보다 "왜 지금 배울 수 있는지"로 답해야 함 |
| TypeORM, Redis, Socket.io, Docker, Cron Job | 이력서상 직접 언급 없음(FastAPI/Lambda 등 인접 경험은 있음) | 개념은 설명 가능해도 실무 경험 부족 |

**이 갭을 어떻게 다룰 것인가 — 회피하지 말고 아래 원칙으로 정면 답변**

1. **거짓말하지 않는다.** "해봤습니다"로 둘러대면 꼬리질문 한두 개에 바로 드러남 — 신뢰를 완전히 잃음.
2. **전이 가능한 경험으로 연결한다.** NestJS는 모르지만, Spring Boot로 Controller-Service-Repository 계층형 아키텍처를 직접 짜봤고, FastAPI로 또 다른 백엔드 프레임워크를 다뤄본 경험이 있음 — "새 프레임워크의 문법이 아니라 계층형 아키텍처의 사고방식 자체는 이미 갖고 있다"는 논리.
3. **학습 속도를 증명한다.** 이 회사가 스스로 강조하는 "AI 코딩 도구로 빠르게 캐치업하되 이해하지 못한 채로 두지 않는다"는 태도를 그대로 가져와서, "Flutter/NestJS도 같은 방식(AI 도구 활용 + 원리 이해 + 테스트로 검증)으로 캐치업할 자신이 있다"고 답변.
4. **부족한 부분을 먼저 인정하고, 어디까지 채웠는지/채울 계획인지를 구체적으로 말한다.** (예: 면접 전 NestJS 공식 튜토리얼로 간단한 CRUD API를 만들어봤다면 그 경험을 언급 — 실제로 해보는 걸 추천)

> [!warning] 실전 팁
> 면접 전에 **NestJS로 간단한 CRUD API 하나, Flutter로 화면 하나**라도 직접 만들어보고 가는 걸 강력 추천합니다. "공부했다"가 아니라 "만들어봤다"로 답할 수 있으면 갭에 대한 답변의 설득력이 완전히 달라집니다.

| AI 코딩 도구 실무 활용 + 추상적 설계·구체적 테스트로 통제권 확인 | VitalVET 커스텀 린트 훅, 서브에이전트, MetaDx Office 단위 테스트 25개 + CI |

## ❓ HIT 맞춤 예상 질문

### 갭 관련

**Q. NestJS 실무 경험이 없으신데, 지원하신 이유가 뭔가요?**
- 위 "갭을 다루는 원칙" 참고. Spring Boot로 계층형 아키텍처를 직접 설계해본 경험 + FastAPI 경험으로 "프레임워크는 달라도 백엔드 아키텍처 사고는 이미 있다"는 논리, 그리고 회사가 명시한 "AI 도구로 빠르게 캐치업하되 원리를 이해한다"는 태도로 마무리

**Q. Flutter는 완전히 처음이신 것 같은데, 실무 투입까지 얼마나 걸릴 것 같나요?**
- > 채워넣기: 면접 전 직접 Flutter로 간단한 화면을 만들어본 경험이 있다면 그걸 근거로 구체적인 답변 준비. React의 컴포넌트/상태 관리 개념(선언적 UI, 위젯 트리)이 Flutter의 위젯 시스템과 유사하다는 논리도 활용 가능

**Q. 이 공고는 백엔드(NestJS)·프론트(React)·모바일(Flutter)을 동시에 3년 이상 요구하는데, 현실적으로 세 영역을 모두 깊게 하긴 어렵지 않나요? 본인은 어느 쪽에 더 강점이 있나요?**
- 솔직하게 "React/TypeScript가 가장 강하고, 백엔드는 필요에 따라 API를 직접 다뤄온 경험이 있다"는 우선순위를 명확히 말하는 게 애매하게 다 잘한다고 하는 것보다 신뢰를 줌

### 도메인·제품 관련

**Q. 저희 제품(WEDDINGPRO)을 보고 어떤 생각이 들었나요? 어떤 기능을 더 만들어보고 싶나요?**
- > 채워넣기: 실제로 링크(hitdxsolution.web.app)를 들어가보고 상담/계약/정산 플로우가 어떻게 구성돼 있는지 파악해두기. "다음 이력서 프로젝트처럼 시간축 기반 UI(입원 차트 경험)가 상담 이력 타임라인에도 적용될 수 있을 것 같다"는 식의 구체적 아이디어를 준비하면 좋음

**Q. B2B SaaS에서 여러 웨딩업체(테넌트)의 데이터를 다뤄야 할 텐데, 멀티테넌시 관점에서 고려해야 할 게 뭐가 있을까요?**
- 데이터 격리(tenant_id 기반 필터링 또는 스키마 분리), 권한 관리(업체별 관리자/직원 권한), 성능(테넌트별 인덱싱) 등 원론적으로 답변 가능하도록 준비 — > 채워넣기: 실제 겪은 경험이 있다면 연결

### AI 활용 관련 (강점 영역 — 자신 있게 답변)

**Q. AI 코딩 도구를 실무에서 구체적으로 어떻게 쓰시나요? "이해하지 못한 채로 넘어가지 않는다"는 걸 본인 방식으로 설명해주세요.**
- [[면접준비/AI-활용-경험\|AI-활용-경험]] 문서의 스크립트를 그대로 활용 — 커스텀 린트 훅, 서브에이전트 역할 분리, 단위 테스트 25개, CI 게이트 등을 "AI 산출물에 대한 통제권을 유지하는 장치"라는 틀로 설명

**Q. 레거시 코드를 파악하거나 장애 원인을 찾을 때 AI를 어떻게 활용하시나요?**
- > 채워넣기: 실제 사용 경험이 있다면 구체적 사례. 없다면 "지금까지는 신규/개선 작업 위주로 AI를 썼지만, 레거시 파악에는 [전략]으로 활용할 것 같다"는 논리적 답변도 가능

### 조직·환경 관련

**Q. 작은 조직에서 혼자 여러 영역(백엔드/프론트/모바일)을 오가며 일해야 할 수도 있는데 괜찮으신가요?**
- CancerVET에서 Python/FastAPI/AWS Lambda까지 다뤄본 경험, VitalVET에서 성능·인프라·팀 간 협업까지 폭넓게 관여한 경험을 근거로 "영역을 가리지 않고 필요한 걸 배워서 처리하는 데 익숙하다"고 답변

**Q. TDD 경험이 있으신가요? 어느 정도까지 테스트를 우선시하나요?**
- MetaDx Office의 "오류 시 파급력이 큰 로직 우선 테스트" 전략을 리스크 기반 접근으로 설명, TDD(테스트 먼저 작성)까지는 아니었다면 솔직히 인정하고 지향점으로 답변

## 🗣️ 이 회사용 지원동기 스크립트 초안

> "채용공고 마지막에 있는 문장을 보고 지원을 결심했습니다. 'AI 코딩 도구는 이미 실무의 기본값이지만, 왜 이렇게 동작하는지 파악하는 속도까지 함께 끌어올린다'는 부분이었는데, 이게 제가 지금 회사에서 해온 일과 정확히 같은 방향이었습니다. AI 코드 생성이 늘면서 아키텍처 규칙이 무너지는 문제를, 문서화에 그치지 않고 커밋 전에 자동으로 차단하는 린트 훅으로 해결했고, 리스크가 큰 로직에는 단위 테스트를 두고 CI로 검증했습니다. WEDDINGPRO의 상담-계약-정산 흐름도, 제가 다뤘던 전자결재 시스템의 승인 워크플로우·금액 규칙과 구조적으로 닮아 있다고 느꼈습니다. NestJS와 Flutter는 직접 실무로 다뤄본 적은 없지만, Spring Boot와 FastAPI로 이미 계층형 백엔드 아키텍처를 설계해본 경험이 있고, 지금 회사가 강조하는 것과 같은 방식 — AI 도구로 빠르게 캐치업하되 원리를 이해하고 테스트로 검증하는 방식 — 으로 충분히 빠르게 채워나갈 수 있다고 생각합니다."

> 채워넣기: 실제 면접에서는 이걸 그대로 읽지 말고, 본인 말투로 자연스럽게 재구성해서 연습하기
